2. USER'S PRODUCT REQUIREMENTS AND DECISIONS
==========================================================================

CONFIRMED TARGET:
- Original BO2 Zombies is the core game, across ALL BO2 Zombies maps.
  One-map prototyping is a validation stage, not a reduced release scope.
- BL2 supplies native guns, drops, characters, shields, grenades, class upgrades
  and its actual inventory screen/HUD. Preserve shield/grenade indicators, ammo,
  XP/level progress and level-up feedback (explicit user HUD decision).
  World isolation must retain desired native HUD and gun/hand layers. HUD health
  must reflect BO2-authoritative match health; donor campaign values are not proof
  of correct Zombies integration. Do not substitute a lookalike inventory or
  hand-authored weapon behavior without an explicit direction change.
- "Class upgrades" includes class-mod equipment as a working interpretation;
  the complete intended scope has not been specified.
- PROGRESSION RESETS WITH EVERY NEW ZOMBIES MATCH. XP, level gains and skill
  progression return to a starting baseline. That baseline is not chosen yet.
- A new round, revive, adapter refresh or bridge reconnect is NOT a new match.
  Future match identity must be distinct from transport/session identifiers.
- Isolate mod progression from normal BL2 campaign saves. Do not reset those saves.
- The release should ask users for their own BO2 and BL2 installation locations.
  Ship authored integration code, not source-game assets or saves.

PROPOSED / UNDECIDED:
- Native skill trees remain a "maybe" feature. If included, leveling should let
  a player complete a chosen build within one Zombies match. Configurable 10x XP
  or higher is a tuning candidate, not an implemented multiplier or guarantee.
- A full chosen build does not automatically mean maximizing every skill tree.
- Action skills, starting level/skill points, target completion round, XP awards,
  level cap, starting loadout and item carryover need specification.
- Mystery Box behavior is explicitly undecided. Do not redesign it by default.
- Pack-a-Punch mapping, menu pause behavior and placeholder world-drop models
  have not been selected. Co-op is a later stage, not working functionality.
- Pre-match lobby character selection is the current recommendation, not a
  validated implementation. The user requested research; no selector was built.
- HUD layout/mapping for BO2 rounds/points and donor minimap/quest information is
  unselected. Keeping level-up UI does not by itself settle skill trees/XP rules.

ARCHITECTURE:
BO2 owns movement/collision, camera, zombies, rounds, player health/death and map
events. BL2 should evaluate its own equipment and inventory. Shields need an
explicit absorption-to-BO2-health pipeline; do not run two health authorities.
The bridge translates events/state/input and eventually rendering/audio.
Separate processes and explicit interfaces are the useful parts of MC's supplied
passthrough document. They do not guarantee compatibility or eliminate crashes.
Rust is now used for a sidecar, NOT to restart the abandoned engine rewrite.

4. TWO TRANSPORTS EXIST - DO NOT CONFUSE THEM
==========================================================================

A. EXISTING FILE BOOTSTRAP (live verified)
BO2 GSC -> blacklands_host.txt -> BL2 SDK -> blacklands_reply.txt -> BO2 console.
BL2 also writes blacklands_bl2.json and blacklands_weapon.json.
Both adapters sample approximately every 0.25 seconds (4 Hz).
Plutonium's observed mailbox is:
  %LOCALAPPDATA%\Plutonium\storage\t6\raw\scriptdata
The "raw" component is essential. Do not revert to storage/t6/scriptdata.

BO2 frame:
  BLPT1|seq|game_ms|x|y|z|pitch|yaw|roll|health|round|weapon|END
Reply:
  BLPT1|host_seq|donor_seq|ACK
ACK is diagnostic only; BO2 does not evaluate incoming text or apply commands.
The current BO2 probe samples only when exactly ONE player exists.

B. OPTIONAL RUST IPC (synthetic and native pose/ACKs verified)
BL2 runtime.py -> nonblocking UDP on 127.0.0.1 -> Rust sidecar -> ACK.
It sends primitive pose/weapon identity, capped at 60 Hz, not guaranteed 60 Hz.
BO2 is NOT connected to this fast channel. No rendering data is transported.
One datagram = bounded JSON pose. Lossy latest-state observations only.
Do not use this channel unchanged for damage, XP, pickups, saves or other actions
that need reliable delivery, deduplication and durable effects.
See docs/RUNTIME.md for the full schema and lifecycle contract.

C. SEPARATE FINITE MENU CONTROL (new UI operation, not gameplay transport)
Panel -> blacklands_menu_request.json -> SDK menu_control -> native Inventory.
blacklands_menu_status.json reports heartbeat and observed request outcome.
Read docs/MENU_CONTROL.md. Explicit start_menu_control.py activation;180s max,
random activation tied to donor session, exact open_inventory action only,
contiguous request seq1..128, expiry<=2s, at-most-once native invocation. Successful
function return is not success: require native Inventory screen3 to appear.
Never add arbitrary commands or reuse this UI experiment as combat/persistence.

FILE: adapters/bo2/blacklands_probe.gsc
  init() starts blacklands_probe(); exits on level "game_ended".
  sequence: per-map diagnostic counter, wraps after 2,000,000,000.
  last_reply: suppresses duplicate console ACK messages.
  players/player: sampled local actor; requires players.size == 1.
  p/a: native origin and getplayerangles(); round: level.round_number or 0.
  frame: BLPT1 wire text; wait 0.25 controls the bootstrap sample rate.

FILE: adapters/bl2/blacklands_passthrough/__init__.py
  Main Mods menu probe v0.2.0. enable(), disable(), sample().
  sample is hooked to Engine.PlayerController:PlayerTick; UObject reads occur
  on that game thread. Main probe and optional modules have distinct hooks.
  _mailbox: Path or None; None disables sampling.
  _session: new UUID on enable; _seq: diagnostic sample counter.
  _next_sample: 4 Hz limiter; _last_error: repeated-warning suppression.
  BLACKLANDS_MAILBOX: optional explicit environment override; otherwise use the
  observed LOCALAPPDATA mailbox. An invalid explicit path does not fall back.
  host_seq: validated BO2 sequence being acknowledged, not a gameplay command.

FILE: adapters/bl2/blacklands_passthrough/weapon.py

  DEFINITION_PATHS: 14 type/balance/manufacturer/part/prefix/title object paths.

  STATE_FIELDS: bIsFiringWeapon, bAmmoRefilledDuringReload, bManualReload.

FILE: adapters/bl2/blacklands_passthrough/events.py
  Optional finite read-only diagnostic; start(seconds=180), stop(), flush().
  _specs: 8 POST callbacks (ammo, fire, projectile, reload, damage display,
  projectile construction and WillowAIPawn.TakeDamage).
  _tick: PlayerTick; _impact: ProcessInstantHitBullet.
  _prefix = blacklands.readonly.events. Own identifiers permit cleanup/reload.
  Total currently 12 hooks, including firing PRE and impact PRE/POST.
  _capture is the state dictionary:
    id/session: event capture UUID and main donor session.
    seq/buffer/errors: packet sequence, EventBuffer, callback error count.
    active/reason/started/deadline/next_flush: finite lifecycle/publication.
    shot_id/stack: capture-local firing-call IDs and synchronous contexts.
    projectiles: at most 256 weak-reference associations to original weapons.
    hit_diagnostics: first four primitive argument descriptions.
    impact_id/impacts: separate bullet-impact call contexts, not firing IDs.
  on_fire_begin() assigns a firing-call ID, NOT a universal trigger/shot ID.
  on_event('take_damage') filters InstigatedBy to the local player; uses native
  DamageCauser, never simply the currently equipped gun. Missing causal links
  remain null. impact_id requires matching scoped native weapon AND target.
  on_tick clears leftover contexts, stops stale sessions/deadlines and publishes.
  Hooks return None; never block or re-invoke original game functions.
  SDK WeakPointer is emulated and is not an absolute object-reuse guarantee.

FILE: adapters/bl2/blacklands_passthrough/hit_trace.py
  describe(): bounded primitive reference inspection (default budget 160).
  function_schema(): candidate hit/trace/bullet/impact/shot/fire signatures,

  bullet_schemas(): at most 24 loaded bullet-related classes, 96 properties each.
FILE: adapters/bl2/blacklands_passthrough/start_events.py

FILE: runtime/src/lib.rs
  MAX_BYTES = 8192; STALE_MS = 2000.
  Pose: schema=1, kind=pose, source=bl2, origin=native_bl2 or synthetic_test,
  epoch, token, session, seq, sent_us, position[3], angles[3], weapon/null.

FILE: runtime/src/main.rs
  Bootstrap {epoch,token} arrives via bounded stdin, not printed to logs.
  Binds localhost UDP on a dynamic port; rejects oversized Windows datagrams.
  Publishes endpoint and redacted status JSON; finite duration 1..180 seconds.
  Report native_bl2_online depends on progressing native-labeled samples.
  No gameplay command handler exists. Producer labels are not attestation.

FILE: bridge/runtime_ipc.py
  MAX_BYTES = 8192; ENDPOINT_FILE = blacklands_runtime_endpoint.json.
  read_endpoint(): checks localhost, sole bl2_pose_readonly capability, schema.
  Publisher: endpoint, origin, session, seq, started, last_ack, ack_seq,
  ack_count, last_rtt_ms, skipped, closed, pending, socket.
  send()/poll(): nonblocking; max 128 pending, max 8 replies drained per sample.
  Replies must match an outstanding seq/sent_us and current epoch/session.
  status(): >=2 ACKs and last ACK within 2 seconds required for online.
  Local credentials prevent accidental mixups, not hostile same-user access.
FILE: bridge/runtime_host.py
  Launches Rust with fresh UUID epoch/token; msvcrt launcher lock prevents two
  cooperating launchers owning one mailbox. --seconds defaults/max 180.
  Default report work/runtime-status.json; default binary under runtime-target.

  report.samples holds timespan, dimensions, foreground classification, hashes,

DO NOT REPEAT THESE FAILED ASSUMPTIONS:
- Damage display ordering does not identify the originating shot.
- Pistol hits can arrive after firing returns, with multiple rounds in flight.
  Assigning the most recent firing ID would fabricate causality.
- ProcessInstantHitBullet exists in reflection, but our hook recorded no calls
  during actual hits. Existence/registration alone is not execution proof.
- ProjectileDefinitionFire/ExecuteProjectileFiredConstructEvent association has
  synthetic coverage only. No native spawned-projectile link was seen in this test.
- A native weapon path identifies a local object, not a cross-session item ID.
- A callback's damage argument is not proof of target health loss or a universal
  damage formula. BL2 test-enemy damage cannot be blindly reused for BO2 zombies.
- UDP ACKs confirm accepted telemetry, not execution of game actions.
- bDisableWorldRendering keeps the native HUD but removes first-person guns too.
  Arms DepthPriorityGroup=1 alone does not exempt them from this viewport switch.
  An opaque black background is not alpha; black-keying would damage HUD artwork.
- Controller visibility arrays were not exposed by this SDK/build; property names
  from another UE3 build are not usable native offsets or proof of a working API.
- Native XP pool max100,000,000 was not next-level threshold899,363 at level30.
  Menus/HUD currently show the normal donor character, not a new Zombies build.
- External inventory viewing is verified. Native inventory request and foreground
  handoff now have a separate finite control trial; do not equate that with input
  forwarding, a single playable window, host pause or an inventory embedded in BO2.
- SDK revision b1852aa4 add_hook can insert a second callback and return false.
  Player/menu modules now verify has_hook after owned cleanup/add; stop recovers
  identifiers even with lost Python state. Other optional adapters still use the
  older return-value check: revisit before simultaneous activation, not blind retry.
- The old Rust prototype contains authored approximation mechanics; those are
  not proof or implementation of this passthrough project's native systems.
